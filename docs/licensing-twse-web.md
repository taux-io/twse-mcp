# 證交所網站端點（`/rwd`、`exchangeReport`）的授權依據與查證紀錄

本服務目前只用證交所 OpenAPI（`openapi.twse.com.tw`，275 個資料集的一部分）。這份文件回答一個問題：
**證交所網站上那些可以指定日期的報表端點（`www.twse.com.tw/rwd/zh/...`、`/exchangeReport/...`），能不能加進來？**
它補的是最大的缺口——OpenAPI 只有最新一個交易日（swagger 143 個路徑，沒有任何一個帶參數）。

查證日期：**2026-10-21**。與 [licensing-taifex.md](licensing-taifex.md) 同一套方法：預設禁止，
看豁免範圍是否涵蓋。結論先講：**只有 `BWIBBU_d` 在豁免範圍內；`T86`、`BFI82U`、`STOCK_DAY` 不在。**

## 一、預設是禁止的

[證交所網站使用條款](https://www.twse.com.tw/zh/terms/use.html)（頁面沒有條號，以標題引用；
下面是 2026-10-21 從頁面原文取出，不是摘要）有兩段相關：

**「下載軟體或資料」**

> 非依臺灣證券交易所同意之方式或經臺灣證券交易所同意者，禁止透過包括但不限於自動化裝置、
> 指令碼、自動程式、蜘蛛程式、爬蟲程式或擷取程式等方式下載本網站之軟體或資料。

**「智慧財產權及其他相關權利、利益的保護」**

> 任何人除非事前取得台灣證券交易所或其他權利人之書面同意，不得逕自使用、修改、重製、公開播送、
> 改作、散布、發行、公開發表、進行還原工程、解編或反向組譯，**但臺灣證券交易所已授權「政府資料
> 開放平臺」提供公眾使用之本網站資料，不在此限。**

另有「認知與同意」：證交所有權於任何時間修改使用條款，繼續使用視為同意；「服務變更及通知」：
可不經通知隨時修改或停止服務。

兩段合起來：**自動化下載網站資料是被禁止的（第一段），散布也是（第二段），唯一的出口是
「已授權 data.gov.tw 的資料」。** 範圍由 data.gov.tw 界定，不由「端點打得開」界定。

## 二、豁免範圍：data.gov.tw 上證交所登錄了什麼

做法：data.gov.tw 的 `api/v2/rest/dataset/{id}` 可以逐筆查。證交所的資料集 ID 集中在 11540–11873，
我掃了 11000–12700：全區間篩內容提到 `openapi.twse.com.tw` 的，11400–12100 另外放寬到 `臺灣證券交易所`、`twse.com.tw`。
**共 44 筆，授權全是政府資料開放授權條款－第 1 版（OGDL v1）**；放寬篩法沒有多出任何一筆。

和這次要問的四個端點對照：

| 端點 | data.gov.tw 登錄？ | 登錄的資料集 |
|---|---|---|
| `rwd/zh/afterTrading/BWIBBU_d`（個股日本益比、殖利率、股價淨值比，依日期查詢） | **有** | 11764「盤後資訊 > 個股日本益比、殖利率及股價淨值比（依日期查詢）」，下載連結就是 `https://www.twse.com.tw/rwd/zh/afterTrading/BWIBBU_d?response=open_data` |
| `rwd/zh/fund/T86`（三大法人買賣超日報） | **沒有** | 三大法人只登錄了 11655、11656（外資及陸資持股），都不是 T86 |
| `rwd/zh/fund/BFI82U`（三大法人買賣金額統計表） | **沒有** | 同上 |
| `exchangeReport/STOCK_DAY`（個股日成交資訊，單一股票按月） | **沒有** | 登錄的是 11549 `STOCK_DAY_ALL`（全市場最新一日）與 11550、11551（月、年成交），不是 STOCK_DAY |

這個掃描的限度：data.gov.tw 共 52,525 筆資料集，我只掃了 ID 區間並以文字比對，不是窮盡搜尋。
「沒有」的意思是「在證交所資料集聚集的區間裡找不到」，不是證明全站不存在。

### 不能用 TAIFEX 那招

期交所的 `data_gov` 下載通道只服務已登錄的端點，所以 licensing-taifex.md 能用「請求 `data_name`」
當作範圍檢驗。**證交所沒有這個性質：** 四個端點帶 `?response=open_data` 全部回 200 與 CSV，
包括沒登錄的 T86、BFI82U、STOCK_DAY。
所以「能下載 CSV」不證明在豁免內；範圍只能看 data.gov.tw 的登錄紀錄。

## 三、BWIBBU_d：在範圍內，但歷史日期是灰區

已知事實：

- 登錄的下載連結在 `/rwd` 路徑上，所以這個端點本身是 data.gov.tw 授權的取得管道，
  不是旁門；資料集標題明寫「依日期查詢」。
- 同一端點加 `date=20260601&selectType=ALL`（`response=open_data` 或 `json`）能回 2026-06-01 的整份資料；
  不帶 `date` 則是最新一日。OpenAPI 的 `exchangeReport/BWIBBU_d` 已在你的目錄裡，但沒有日期參數。
- 這筆資料集的 `coverageStartedDate` 與 `coverageEndedDate` 是空的：data.gov.tw 沒有聲明涵蓋的期間。

沒有證據可以裁決的問題：**授權範圍是「這個端點」，還是「這個端點目前回的最新一日」？**
標題寫「依日期查詢」支持前者；沒有登錄涵蓋期間、OpenAPI 版不帶日期則留下後者的可能。

我的判讀：前者較可能成立，但這是推論，不是證交所的說法。要消除疑慮只有問證交所
（見 `docs/upstream-reports/2026-09-28-twse-mis-inquiry.md`，那封詢問信到現在還是草稿、沒寄出）。

## 四、T86、BFI82U、STOCK_DAY：不在範圍內

三個都落在第一段（禁止自動化下載）與第二段（禁止重製與散布）之下，而豁免不涵蓋它們。
`?response=open_data` 能打得開不改變這點（見上）。

這與 [ADR 0003](adr/0003-d1-daily-archive.md) 一致：那裡也因同一條使用條款而不回補證交所網站的個股歷史查詢，
只自己累積 `STOCK_DAY_ALL`。

## 五、結論：能不能加進 twse-mcp

| 端點 | 結論 |
|---|---|
| `BWIBBU_d`（歷史日期） | **可以，有一個前提：** 灰區判讀見第三節。建議先寄信確認；不想等的話，風險也只在「歷史日期」這一個參數，最新一日本來就在目錄裡。 |
| `T86`、`BFI82U`、`STOCK_DAY` | **不能加。** 不在豁免內，加了就是自動化下載加散布未授權資料。 |

替代方案（不碰灰區）：

- **D1 自己累積。** ADR 0003 已經對 `STOCK_DAY_ALL` 這麼做。對 `BWIBBU_ALL`（已在 OpenAPI 目錄）、
  `MI_MARGN`、`TWTB4U` 等有登錄的資料集，同樣可以排程累積，歷史從開始存的那天起算。
  這條路授權乾淨，代價是沒有回補、要佔 D1 空間（免費方案 500 MB）。
- **改用有登錄的相近資料。** 三大法人只有外資持股（11655、11656）登錄；T86、BFI82U 的資料不能替代。

## 六、這個結論何時會失效

- **證交所修改使用條款或 data.gov.tw 的登錄時。** 條款可不經通知修改。
- **證交所把 T86、BFI82U、STOCK_DAY 登錄到 data.gov.tw 時。** 那時再重跑第二節的掃描。
- **證交所回覆詢問信時。** 回覆比這份推論優先。

## 七、本文件沒有驗證的

- 沒有從 Cloudflare Workers 的出口 IP 試過這些端點，只從本機試過；證交所會不會擋雲端沒有測。
- 掃描不是窮盡的（見第二節）。
- 條款頁面沒有日期，我看到的版本只能標查證日。
- 這是技術性的條款閱讀，不是法律意見。
