## 問題一：上市公司綜合損益表（金控業）— OpenAPI 的欄位名稱與原始 CSV 錯位

| 項目 | 內容 |
|---|---|
| 資料集 | 上市公司綜合損益表(金控業)，[data.gov.tw/dataset/91999](https://data.gov.tw/dataset/91999) |
| OpenAPI 端點 | `https://openapi.twse.com.tw/v1/opendata/t187ap06_L_fh` |
| 原始 CSV | `https://mopsfin.twse.com.tw/opendata/t187ap06_L_fh.csv` |
| 資料期間 | 115 年第 2 季（出表日期 1150926） |
| 影響範圍 | OpenAPI 回傳的 **13 家金控全數**；原始 CSV **正確** |

### 現象

OpenAPI（JSON）與原始 CSV 的**數值完全相同、順序也相同**，但兩者的**欄位名稱清單不同**。
OpenAPI 的名稱清單比 CSV 多了一個「其他收益及費損淨額」、少了「所得稅（費用）利益」，
中間一段因而整段錯位一格。以 2880 華南金為例：

| 位置 | 原始 CSV 欄名（正確） | OpenAPI 欄名 | 數值（千元） |
|---|---|---|---|
| 6 | 利息淨收益 | 利息淨收益 | 16,030,332 |
| 7 | **利息以外淨收益** | 其他收益及費損淨額 | 24,700,750 |
| 8 | **淨收益** | 利息以外淨收益 | 40,731,082 |
| 9 | **呆帳費用、承諾及保證責任準備提存** | 淨收益 | 1,521,964 |
| 10 | **保險其他營業成本** | 呆帳費用、承諾及保證責任準備提存 | -47,604 |
| 11 | **營業費用** | 保險負債準備淨變動 | 18,469,859 |
| 12 | **繼續營業單位稅前損益** | 營業費用 | 20,786,863 |
| 13 | **所得稅（費用）利益** | 繼續營業單位稅前損益 | 3,423,689 |
| 14 | 繼續營業單位本期淨利（淨損） | 繼續營業單位本期淨利（淨損） | 17,363,174 |

（位置 14 之後兩邊欄名一致，數值正確。）

### 對使用者的影響

依 OpenAPI 欄名讀取的程式會得到錯誤的數字，而且**沒有任何錯誤訊息**。例如：

- 「繼續營業單位稅前損益」讀到 3,423,689（實為所得稅），**比稅後淨利 17,363,174 還小**；
- 「淨收益」讀到 1,521,964（實為呆帳費用），不到實際淨收益 40,731,082 的 4%；
- 「營業費用」讀到 20,786,863（實為稅前損益）。

### 我們如何確認這不是巧合

以下三條會計恆等式，用 **OpenAPI 欄名**直接代入都不成立；改用「錯位一格」的對應代入，
**13 家金控全部精確成立**（差額為 0）：

| 檢驗 | 用 OpenAPI 欄名解讀（應成立的式子） | 用錯位一格解讀 |
|---|---|---|
| A | 利息淨收益 + 利息以外淨收益 = 淨收益 | 13/13 成立 |
| B | 淨收益 − 呆帳費用 − 保險成本 − 營業費用 = 稅前損益 | 13/13 成立 |
| C | 稅前損益 − 所得稅 = 本期淨利 | 13/13 成立 |

同時我們也檢查了其他五個業別（一般業、金融業、證券期貨業、保險業、異業）的損益表與
六個業別的資產負債表：**只有金控業的損益表有此問題**；所有資產負債表「資產＝負債＋權益」皆成立，
一般業 1,042 家「稅前 − 所得稅 ＝ 繼續營業單位淨利」皆成立。

### 重現步驟

**1. 用 curl 取兩份資料並目視比對華南金那一列：**

```bash
curl -s -H 'Accept: application/json' https://openapi.twse.com.tw/v1/opendata/t187ap06_L_fh \
  | python3 -c 'import json,sys; r=[x for x in json.load(sys.stdin) if x["公司代號"]=="2880"][0]; [print(k,"=",v) for k,v in r.items()]'

curl -s https://mopsfin.twse.com.tw/opendata/t187ap06_L_fh.csv | grep -E '^"?出表日期|2880'
```

**2. 用 Python 對全部金控驗證三條恆等式（只用標準函式庫）：**

先用 curl 下載（curl 走作業系統的憑證庫；部分 macOS 上的 Python 沒有安裝 CA 憑證，直接連線會失敗，
這與貴單位的憑證無關），再用 Python 計算：

```bash
curl -s -H 'Accept: application/json' https://openapi.twse.com.tw/v1/opendata/t187ap06_L_fh -o fh.json
python3 check_fh.py fh.json
```

`check_fh.py`：

```python
import json, sys

rows = json.load(open(sys.argv[1], encoding="utf-8"))
n = lambda v: float(str(v).replace(",", "") or 0)

for r in rows:
    # 依 OpenAPI 欄名直接解讀：應該成立，實際不成立
    as_named = n(r["利息淨收益"]) + n(r["利息以外淨收益"]) == n(r["淨收益"])
    # 依「錯位一格」解讀：三條全部成立
    a = n(r["利息淨收益"]) + n(r["其他收益及費損淨額"]) == n(r["利息以外淨收益"])
    b = n(r["利息以外淨收益"]) - n(r["淨收益"]) - n(r["呆帳費用、承諾及保證責任準備提存"]) - n(r["保險負債準備淨變動"]) == n(r["營業費用"])
    c = n(r["營業費用"]) - n(r["繼續營業單位稅前損益"]) == n(r["繼續營業單位本期淨利（淨損）"])
    print(r["公司代號"], r["公司名稱"], "依欄名:", as_named, "| 錯位一格 A/B/C:", a, b, c)
```

2026-09-26 15:47 實測輸出：13 家皆為 `依欄名: False | 錯位一格 A/B/C: True True True`。

### 建議修正

將 `t187ap06_L_fh` 的 OpenAPI 欄位名稱清單（以及 `swagger.json` 內對應的 schema）改為與原始 CSV
表頭一致：移除「其他收益及費損淨額」，「保險負債準備淨變動」改為「保險其他營業成本」，
並在「繼續營業單位稅前損益」之後加入「所得稅（費用）利益」。

## 問題二：集中市場漲跌證券數統計表 — 原始檔自 2026-06-05 起未再產生

| 項目 | 內容 |
|---|---|
| 資料集 | 集中市場漲跌證券數統計表（可在政府資料開放平臺以此名稱搜尋） |
| OpenAPI 端點 | `https://openapi.twse.com.tw/v1/opendata/twtazu_od` |
| 原始 CSV | `https://mopsfin.twse.com.tw/opendata/twtazu_od.csv` |

### 現象

2026-09-26 15:48（台灣時間）取得的結果：

| 來源 | `Last-Modified` 標頭 | 內容的日期 |
|---|---|---|
| 原始 CSV（mopsfin） | **Fri, 05 Jun 2026 05:44:50 GMT** | 資料日期 1150605 |
| OpenAPI `twtazu_od` | Fri, 25 Sep 2026 21:24:22 GMT | 出表日期 1150605 |
| 對照：OpenAPI `MI_INDEX`（每日收盤行情） | Fri, 25 Sep 2026 21:21:28 GMT | 日期 1150924 |
| 對照：OpenAPI `STOCK_DAY_ALL`（個股日成交） | Fri, 25 Sep 2026 21:20:44 GMT | Date 1150924 |

**原始 CSV 自 2026-06-05 起就沒有再產生**；OpenAPI 每晚照常重新發布，但發布的是同一份舊檔，
所以 OpenAPI 的 `Last-Modified` 是新的、內容卻停在 115 年 6 月 5 日。同一批次的其他每日資料
都已更新到 115 年 9 月 24 日。

### 重現步驟

```bash
# 原始 CSV：看 Last-Modified 與內容日期
# （用 GET 取標頭：這台伺服器的 HEAD 回應不帶 Last-Modified）
curl -s -D - -o /dev/null https://mopsfin.twse.com.tw/opendata/twtazu_od.csv | grep -i last-modified
curl -s  https://mopsfin.twse.com.tw/opendata/twtazu_od.csv | head -3

# OpenAPI：內容日期仍為 1150605
curl -s -H 'Accept: application/json' https://openapi.twse.com.tw/v1/opendata/twtazu_od

# 對照：同一批次的其他每日資料已是最新交易日
curl -s -H 'Accept: application/json' https://openapi.twse.com.tw/v1/exchangeReport/MI_INDEX \
  | python3 -c 'import json,sys; print(sorted({r["日期"] for r in json.load(sys.stdin)}))'
```

### 建議修正

請確認產生 `mopsfin.twse.com.tw/opendata/twtazu_od.csv` 的排程在 2026-06-05 之後是否中斷。
另外，原始 CSV 的日期欄名是「資料日期」，OpenAPI 是「出表日期」，兩者語意不同，建議一併統一。
